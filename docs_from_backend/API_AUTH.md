# API: Авторизация и пользователи

Базовый префикс: **`/api`**.

Базовый путь: **`/api/auth`**.

Эндпоинты **register**, **login** и **refresh** — публичные. Остальные требуют **JWT** (заголовок `Authorization: Bearer <access_token>`). Смена роли дополнительно доступна только пользователям с ролью **admin**.

---

## Эндпоинты

### Регистрация

**`POST /api/auth/register`**

Создаёт пользователя и возвращает пару токенов. Роль по умолчанию — **customer**.

**Тело (JSON):**

| Поле       | Тип    | Обязательное | Описание |
|------------|--------|--------------|----------|
| `email`    | string | да           | Email (валидный формат). |
| `password` | string | да           | Пароль, минимум 6 символов. |
| `username` | string | да           | Имя пользователя, минимум 3 символа. |

**Ответ:** объект с полями `user`, `access_token`, `refresh_token`.

- `user`: `{ id, email, username, role }`
- `role` — одна из: `customer`, `moderator`, `support`, `manager`, `admin`

**Ошибки:** 409 — пользователь с таким email уже существует.

---

### Вход (логин)

**`POST /api/auth/login`**

Проверяет email и пароль, возвращает пару токенов.

**Тело (JSON):**

| Поле       | Тип    | Обязательное | Описание |
|------------|--------|--------------|----------|
| `email`    | string | да           | Email (валидный формат). |
| `password` | string | да           | Пароль. |

**Ответ:** объект с полями `user`, `access_token`, `refresh_token` (формат как у register).

**Ошибки:** 401 — неверный email или пароль.

---

### Обновление токенов

**`POST /api/auth/refresh`**

По валидному refresh-токену выдаёт новую пару access и refresh токенов. Старый refresh после использования остаётся в БД до истечения срока; при следующем вызове refresh используется уже новая пара.

**Тело (JSON):**

| Поле           | Тип   | Обязательное | Описание |
|----------------|-------|--------------|----------|
| `refresh_token`| string| да           | Токен, полученный при login/register или при предыдущем refresh. |

**Ответ:** `{ access_token, refresh_token }` (без объекта `user`).

**Ошибки:** 401 — токен невалиден или истёк.

---

### Текущий пользователь (профиль)

**`GET /api/auth/me`**

**Требует:** JWT.

Возвращает данные текущего пользователя без пароля.

**Ответ:** `{ id, email, username, role }`.

**Ошибки:** 401 — нет или невалидный/истёкший токен.

---

### Выход (логаут)

**`POST /api/auth/logout`**

**Требует:** JWT.

Удаляет запись токенов пользователя из БД. Access и refresh токены становятся недействительными.

**Ответ:** `{ message: "Logged out successfully" }`.

**Ошибки:** 401 — нет или невалидный токен.

---

### Удаление аккаунта

**`DELETE /api/auth/account`**

**Требует:** JWT.

Удаляет токены и пользователя. Требуется подтверждение паролем.

**Тело (JSON):**

| Поле       | Тип   | Обязательное | Описание |
|------------|-------|--------------|----------|
| `password` | string| да           | Пароль текущего пользователя. |

**Ответ:** `{ message: "Account deleted successfully" }`.

**Ошибки:** 400 — пользователь не найден; 401 — неверный пароль.

---

### Смена роли пользователя

**`PATCH /api/auth/users/:id/role`**

**Требует:** JWT и роль **admin**.

Меняет роль пользователя с указанным `id`. Используется для назначения moderator, support, manager, admin.

**Тело (JSON):**

| Поле  | Тип   | Обязательное | Описание |
|-------|-------|--------------|----------|
| `role`| string| да           | Одно из: `customer`, `moderator`, `support`, `manager`, `admin`. |

**Ответ:** объект пользователя с обновлённой ролью: `{ id, email, username, role }`.

**Ошибки:** 400 — пользователь не найден; 401 — нет/невалидный токен; 403 — недостаточно прав (не admin).

---

## Коды ответов

- **200** — успешный запрос (me, logout, delete account, update role).
- **201** — не используется (register/login возвращают 200 с токенами).
- **400** — невалидные данные (DTO), пользователь не найден (account, role).
- **401** — неверные учётные данные, невалидный/истёкший токен или refresh_token.
- **403** — смена роли доступна только admin.
- **409** — конфликт (email уже занят при регистрации).

---

## Роли

| Значение   | Описание |
|------------|----------|
| `customer` | Покупатель (по умолчанию при регистрации). |
| `moderator`| Модерация отзывов, контента. |
| `support`  | Поддержка, просмотр заказов. |
| `manager`  | Товары, заказы, купоны, точки выдачи. |
| `admin`    | Полный доступ, управление ролями и настройками магазина. |

Подробнее: [API_ROLES.md](API_ROLES.md) и [ROLES.md](../ROLES.md) в корне проекта.

## Использование токенов на фронтенде

1. После **register** или **login** сохранять `access_token` и при необходимости `refresh_token` (например в памяти или httpOnly cookie).
2. Для защищённых запросов добавлять заголовок: `Authorization: Bearer <access_token>`.
3. При ответе **401** на запрос с токеном — попробовать обновить пару через **POST /api/auth/refresh**; при успехе повторить исходный запрос с новым `access_token`. Если refresh вернул 401 — перенаправить на страницу входа.
4. При **logout** или удалении аккаунта — очистить сохранённые токены на клиенте.

## Переменные окружения

- `JWT_SECRET` — секрет для подписи JWT.
- `JWT_ACCESS_TOKEN_EXPIRES_IN` — время жизни access-токена (например `15m`).
- `JWT_REFRESH_TOKEN_EXPIRES_IN` — время жизни refresh-токена (например `7d`).
