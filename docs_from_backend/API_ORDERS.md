# API: Заказы

Базовый префикс: **`/api`**.

Все эндпоинты требуют **JWT** (заголовок `Authorization: Bearer <access_token>`). Создавать заказы и просматривать свои может любой авторизованный пользователь; список всех заказов и смена статуса — только **MANAGER** и **ADMIN**.

Базовый путь: **`/api/orders`**.

---

## Статусы заказа

| Значение   | Описание |
|-----------|----------|
| `pending` | Оформлен, ожидает подтверждения. |
| `confirmed` | Подтверждён магазином. |
| `shipped` | Передан в доставку / отправлен. |
| `delivered` | Доставлен. |
| `cancelled` | Отменён (остатки по позициям возвращаются на склад). |

---

## Создать заказ из корзины

**`POST /api/orders`**

Создаёт заказ из текущей корзины пользователя. Корзина должна быть привязана к пользователю (по JWT). После успешного создания позиции корзины очищаются, остатки товаров уменьшаются.

**Тело (JSON):**

| Поле               | Тип    | Обязательное | Описание |
|--------------------|--------|--------------|----------|
| `deliveryType`     | string | да           | `delivery` — доставка, `pickup` — самовывоз. |
| `deliveryAddressId`| number | при доставке | Id адреса доставки (из `/api/addresses`). Обязателен при `deliveryType === 'delivery'`. |
| `pickupLocationId` | number | нет          | Id точки самовывоза (на будущее, при наличии сущности Location). |
| `comment`          | string | нет          | Комментарий к заказу (до 2000 символов). |

**Ответ:** объект заказа с полями `id`, `userId`, `status`, `deliveryType`, `pickupLocationId`, `deliveryAddressId`, `deliveryAddressSnapshot`, `paymentMethod`, `totalAmount`, `comment`, `items`, `createAt`, `updateAt`. В `items` — массив позиций с `productId`, `productName`, `price`, `quantity`.

**Ошибки:** 400 — пустая корзина, не указан адрес при доставке, недостаточно товара на складе.

---

## Список своих заказов

**`GET /api/orders`**

Возвращает заказы текущего пользователя, отсортированные по дате создания (новые первые).

**Ответ:** массив заказов с полями как выше (без вложенного `product` в items).

---

## Список всех заказов (админ/менеджер)

**`GET /api/orders?scope=all`** — только роли **MANAGER**, **ADMIN**.

**Query-параметры (все опциональны):**

| Параметр   | Тип   | Описание |
|------------|-------|----------|
| `scope`    | string | Должен быть `all` для выдачи всех заказов. |
| `status`   | string | Фильтр по статусу: `pending`, `confirmed`, `shipped`, `delivered`, `cancelled`. |
| `dateFrom` | string | Начало периода (ISO 8601 дата). |
| `dateTo`   | string | Конец периода (ISO 8601 дата). |

**Ответ:** массив заказов.

---

## Один заказ по id

**`GET /api/orders/:id`**

- Обычный пользователь: только свой заказ (иначе 403).
- MANAGER/ADMIN: любой заказ.

**Ответ:** объект заказа с позициями и связью `product` у каждой позиции.

---

## Сменить статус заказа

**`PATCH /api/orders/:id/status`** — только **MANAGER**, **ADMIN**.

**Тело (JSON):**

| Поле    | Тип   | Описание |
|---------|-------|----------|
| `status` | string | Один из: `pending`, `confirmed`, `shipped`, `delivered`, `cancelled`. |

При смене статуса на `cancelled` остатки по всем позициям заказа возвращаются на склад.

**Ответ:** обновлённый объект заказа.

---

## Коды ответов

- **200** — успешный запрос.
- **201** — заказ создан (POST).
- **400** — невалидные данные, пустая корзина, нет адреса при доставке, недостаточно товара.
- **401** — нет или невалидный JWT.
- **403** — нет доступа к заказу или к действию (смена статуса).
- **404** — заказ не найден.
