# API: Настройки магазина и точки продаж

Базовый префикс: **`/api`**.

---

## Магазин (Store)

Один магазин на инстанс (при мультитенанте позже — выбор по домену или storeId).

### Получить настройки текущего магазина

**`GET /api/store`** — публичный.

Возвращает настройки активного магазина (или первого в БД). Используется фронтом для отображения названия, контактов, валюты, способов доставки/оплаты из `settings`.

**Ответ:** объект Store: `id`, `name`, `slug`, `logoUrl`, `faviconUrl`, `contactEmail`, `contactPhone`, `legalName`, `inn`, `legalAddress`, `currency`, `timezone`, `locale`, `isActive`, `settings` (JSON), `createAt`, `updateAt`.

**Ошибка 404:** если в БД нет ни одного магазина (сначала создайте магазин через POST).

---

### Создать магазин

**`POST /api/store`** — только **ADMIN** (JWT).

**Тело (JSON):** `name`, `slug` (обязательные); опционально: `logoUrl`, `faviconUrl`, `contactEmail`, `contactPhone`, `legalName`, `inn`, `legalAddress`, `currency`, `timezone`, `locale`, `isActive`, `settings`.

**Ответ:** созданный объект Store.

---

### Обновить текущий магазин

**`PATCH /api/store`** — только **ADMIN**.

Обновляет «текущий» магазин (первый активный или первый в БД). Все поля в теле опциональны.

**Ответ:** обновлённый объект Store.

---

### Обновить магазин по id

**`PATCH /api/store/:id`** — только **ADMIN**.

**Ответ:** обновлённый объект Store.

---

## Точки продаж (Location)

Базовый путь: **`/api/locations`**.

Типы точки: `warehouse` (склад), `pickup_point` (пункт выдачи), `retail` (розничный магазин).

### Список точек (для выбора самовывоза)

**`GET /api/locations`** — публичный.

**Query-параметры:**

| Параметр  | Тип    | Описание |
|-----------|--------|----------|
| `storeId` | number | Фильтр по магазину (при одном магазине можно не передавать). |
| `isActive`| boolean | Только активные точки (по умолчанию можно не передавать). |

**Ответ:** массив объектов Location, отсортированных по `sortOrder`, затем по `id`.

---

### Одна точка по id

**`GET /api/locations/:id`** — публичный.

**Ответ:** объект Location с полем `store` (магазин).

---

### Создать точку продаж

**`POST /api/locations`** — только **MANAGER**, **ADMIN**.

**Тело (JSON):**

| Поле          | Тип    | Обязательное | Описание |
|---------------|--------|--------------|----------|
| `storeId`     | number | нет          | Id магазина; если не передан — берётся текущий (первый активный). |
| `name`        | string | да           | Название точки. |
| `type`        | string | да           | `warehouse` \| `pickup_point` \| `retail`. |
| `city`        | string | да           | Город. |
| `street`      | string | да           | Улица. |
| `building`    | string | да           | Дом/корпус. |
| `apartment`   | string | нет          | Квартира/офис. |
| `postalCode`  | string | нет          | Индекс. |
| `phone`       | string | да           | Телефон. |
| `openingHours`| array  | нет          | График работы, например `[{ "day": 1, "from": "09:00", "to": "18:00" }]` (day: 0–6 или 1–7 по соглашению). |
| `sortOrder`   | number | нет          | Порядок отображения. |
| `isActive`    | boolean| нет          | Активна ли точка (по умолчанию true). |

**Ответ:** созданный объект Location.

---

### Редактировать точку

**`PATCH /api/locations/:id`** — только **MANAGER**, **ADMIN**.

Все поля опциональны (частичное обновление). Формат — как при создании.

**Ответ:** обновлённый объект Location.

---

### Удалить точку

**`DELETE /api/locations/:id`** — только **MANAGER**, **ADMIN**.

**Ответ:** `200` и `{ "message": "Точка продаж удалена" }`.

---

## Связь с заказами

При создании заказа с **самовывозом** (`deliveryType: 'pickup'`) в теле заказа передаётся **`pickupLocationId`** — id точки из `GET /api/locations`. В ответе заказа и при `GET /api/orders/:id` возвращается объект **`pickupLocation`** (адрес и данные точки), если заказ с самовывозом.

---

## Миграции

Таблицы создаются миграциями:

```bash
npm run migration:run
```

Создаются таблицы: **`stores`**, **`locations`**.

Перед использованием создайте хотя бы один магазин (POST /api/store от имени ADMIN).
