# Интернет-магазин на SvelteKit

Фронтенд интернет-магазина, построенный на SvelteKit с поддержкой SSR/SSG для SEO.

## Установка зависимостей

```bash
# Установка основных зависимостей
npm install

# Установка adapter-node для SSR
npm install -D @sveltejs/adapter-node

# Установка Tailwind CSS (опционально, но рекомендуется)
npm install -D tailwindcss postcss autoprefixer
npx tailwindcss init -p
```

## Настройка Tailwind CSS

Если вы установили Tailwind CSS, обновите `tailwind.config.js`:

```js
/** @type {import('tailwindcss').Config} */
export default {
  content: ['./src/**/*.{html,js,svelte,ts}'],
  theme: {
    extend: {},
  },
  plugins: [],
}
```

## Переменные окружения

Создайте файл `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

Переменные читаются при запуске сервера, а не при сборке: один и тот же билд можно запускать с разными адресами.

| Переменная | Зачем | Пример |
|---|---|---|
| `PUBLIC_API_URL` | Адрес API бэкенда. Обращается к нему только сервер витрины, браузер ходит в свой `/api`, поэтому подойдёт и внутренний адрес | `http://localhost:3380/api` |
| `PUBLIC_SITE_URL` | Публичный адрес витрины без слэша на конце. От него строятся canonical, Open Graph, JSON-LD, `sitemap.xml` и `robots.txt`. **В продакшене обязателен:** без него адреса берутся из заголовка `Host`, а за nginx это внутренний `127.0.0.1:3000` | `https://shop.example.ru` |

```env
PUBLIC_API_URL=http://localhost:3380/api
PUBLIC_SITE_URL=https://shop.example.ru
```

## Вход и сессия

Токены бэкенда браузер не видит. Вход, регистрацию и выход выполняет сервер витрины (SvelteKit): пару токенов он хранит в httpOnly-cookie `shop_access` и `shop_refresh`, а номер гостевой корзины — в `shop_guest`. Все запросы браузера к API идут на тот же сайт, в `/api/*`, и сервер пересылает их бэкенду, подставляя вход посетителя (`src/lib/server/proxy.ts`).

- Истекающий access-токен сервер обновляет сам, до отрисовки страницы (`hooks.server.ts`). Параллельные запросы одного посетителя обменивают refresh-токен один раз: повторный обмен бэкенд считает кражей и отзывает сессию.
- Кабинет, корзина, оформление и админка рендерятся на сервере уже с данными. Доступ к ним проверяется на сервере, до отрисовки.
- Вход, сохранённый прежней версией в `localStorage`, при первом визите один раз переезжает в cookie.

Что настроить при развёртывании:

| Где | Переменная | Зачем |
|---|---|---|
| витрина | `ORIGIN` | Публичный адрес, например `https://shop.example.ru`. Без него adapter-node за nginx не знает настоящий адрес, и проверка `Origin` отклонит изменяющие запросы к `/api` |
| витрина | `BODY_SIZE_LIMIT` | Не меньше лимита загрузки фото на бэкенде (`UPLOAD_MAX_MB`, 10 МБ): например `12M`. По умолчанию adapter-node принимает только 512 КБ |
| витрина | `ADDRESS_HEADER`, `XFF_DEPTH` | Если перед витриной стоит nginx: откуда брать IP посетителя (например `X-Forwarded-For` и `1`) |
| бэкенд | `TRUST_PROXY` | Адрес сервера витрины (например `loopback`). Витрина передаёт IP посетителя в `X-Forwarded-For`; без доверия бэкенд считает лимит входов (10 в минуту) общим для всех посетителей |

Cookie ставятся с флагом `Secure`, поэтому production-сборка работает только по https (или на `localhost`). Обмен токенов запоминается в памяти процесса: несколько экземпляров витрины запускайте с привязкой посетителя к экземпляру (sticky sessions).

## Структура проекта

- `src/lib/api/` - API клиент и методы
- `src/lib/stores/` - Svelte stores для состояния
- `src/lib/types/` - TypeScript типы
- `src/lib/components/` - Переиспользуемые компоненты
- `src/routes/` - Страницы и роуты SvelteKit
