# Дорожная карта функций

Сравнение магазина с тем, что ждут от интернет-магазина покупатели и владельцы. Собрано 2026-10-09 по чеклистам 2026 года (Limely, Outerbox, BigCommerce, dev.to), российским гайдам (Habr, Oborot, vc.ru, Skillbox, Workspace), исследованиям Baymard по оформлению заказа, справке Shopify и Яндекс.Метрики, материалам по 54-ФЗ и 152-ФЗ. Инвентаризация «что есть» — по коду фронтенда и бэкенда на ту же дату.

Статусы: **есть** — работает на витрине; **частично** — есть на бэкенде или в данных, но не доведено до экрана; **нет** — отсутствует.

## Что стоит помнить из исследований

- Средний процент брошенных корзин по Baymard — 70 %, причём 42–43 % людей просто смотрели и не собирались покупать. 70 % на дашборде — норма, а не катастрофа.
- Главные причины ухода на оформлении: лишние расходы, всплывшие в конце (48 %), принудительная регистрация (26 %), недоверие сайту при вводе карты (25 %).
- Везде повторяется: мобильность, скорость, полная стоимость до оформления, короткая форма, отзывы, видимые остатки, доступная поддержка.
- Для РФ: оферта, реквизиты, политика ПД и согласие (152-ФЗ), условия возврата; при онлайн-оплате чек по 54-ФЗ обязателен даже для СБП.
- Shopify по умолчанию показывает четыре числа: сессии, продажи, заказы, конверсия. Дашборд должен оставаться таким же сдержанным.

## Приоритеты

### P1 — дёшево и бьёт по деньгам или по закону

1. Дашборд и Яндекс.Метрика с e-commerce `dataLayer`.
2. Оформление гостем: email и телефон вместо аккаунта, с предложением создать его после заказа. Нужна правка бэкенда.
3. Подключить то, что бэкенд уже умеет: экран пользователей с ролями и блокировкой, комментарий к смене статуса, «выйти везде», часы работы точек. Только фронт.
4. Трек-номер в заказе и ссылка на отслеживание в письме «отправлен».
5. Письмо «оцените товар» через несколько дней после `delivered`.
6. Страницы оферты, политики, доставки и возврата внутри витрины; чекбокс согласия при регистрации и оформлении.

### P2 — заметная работа, но меняет магазин

7. Онлайн-оплата через ЮKassa (карты + СБП) с чеками по 54-ФЗ. Зависит от статуса продавца (ИП, ООО, самозанятый) — от него зависит, нужна ли касса.
8. Поиск: подсказки, опечатки и раскладка, артикул, умная пустая выдача. MySQL FULLTEXT или Meilisearch.
9. Фильтры по характеристикам.
10. «Повторить заказ», похожие товары, недавно просмотренные.
11. Подтверждение email при регистрации.
12. Импорт/экспорт товаров CSV.
13. Расчёт доставки СДЭК и карта ПВЗ — только при доставке по стране.

### P3 — когда дойдут руки

14. Варианты товара (SKU-матрица) — меняет модель данных.
15. Напоминания о брошенной корзине, рассылки.
16. Лояльность, сравнение, OAuth-вход, Telegram-бот для менеджеров, push.

## Дашборд

Под словом «отказы» два разных показателя:

- **отказы по заказам** — отменённые заказы: сколько, кто отменил, с какого статуса, причина. Есть в БД (`order_status_history`);
- **отказы в веб-аналитике** (bounce) — визит на одну страницу короче 15 секунд. Как и посещения, считается только счётчиком.

Поэтому два источника.

**A. Своя статистика.** `GET /admin/stats?from&to` на бэкенде (manager/admin), агрегаты по `DATE(create_at)` в часовом поясе магазина, кэш 60 с. Страница `/admin`: 5–8 карточек «цифра + дельта к прошлому периоду», график по дням, таблицы топов. Блоки: продажи, отказы и брошенные корзины, товары (топ, без продаж, закончились), операции (необработанные `pending`, доставка vs самовывоз, точки, купоны), клиенты (новые, повторные), сбои (`mail_failed`).

**B. Посещения и поведение.** Яндекс.Метрика со счётчиком и e-commerce `dataLayer` (просмотр, добавление, удаление, покупка): посещаемость, отказы, источники, устройства, воронка, карты кликов, отчёт «Популярные товары». Вторым шагом ключевые цифры подтягиваются в наш дашборд через Reporting API Метрики с сервера.

Свои события (просмотры товаров, запросы поиска без результатов) — только если Метрики не хватит.
